# BCM5720 native experimental driver

The driver in `net/bcm5720.c` is an independently written GPL-3.0-or-later
implementation using the hardware interface documented in Broadcom
[571X-5720-PG102](https://docs.broadcom.com/doc/571X-5720-PG1XX),
dated 2026-08-05. No bge/tg3 implementation or header is incorporated.
The reference PDF SHA-256 is
`3f887bc455ea01091ce91368700788a27a26b84a1fb1fed259d1ad45ccdd071c`.

The initial profile matches PCI `14e4:165f`, ASIC `05720000` (BCM5720 A0),
copper functions 0/1 and their respective Clause 22 PHY addresses 1/2. It
requires mapped register and APE BARs and card-resident boot firmware to
complete the documented reset handshake and publish a valid factory MAC.
There is no firmware flashing or NVRAM programming.

An active, unknown or inaccessible APE signature, SerDes strap, unsupported
ASIC, stalled NVRAM arbitration, reset/MDIO error or invalid MAC prevents
interface registration. The initial profile does **not** coordinate with active
BMC/APE management firmware, so those cards are deliberately left unreset.
This is a narrower scope than general BCM5720 server adapter support.

The data path uses one 512-entry send ring, one 512-entry standard receive
producer ring with one unused entry, one 512-entry return ring and a 32-byte
legacy status block. Each function owns its buffers, MAC and producer/consumer
indices. TX completion must stay within the outstanding window; RX lengths,
errors, packet-end flags, indices and opaque generation cookies are checked
before passing frames to the network stack. A fatal status or malformed
completion stops PCI bus mastering. DMA storage remains allocated on failure
so late transactions cannot target recycled kernel objects.

The driver polls, negotiates 10/100/1000 copper Ethernet, keeps VLAN tags and
uses software checksums. It does not implement interrupts, RSS, jumbo frames,
SR-IOV, BMC sideband protocols, power suspend/resume or throughput tuning.

Run `python3 tools/test_bcm5720.py --sanitize` and `--32`. They compile the
actual native driver against an independent register/PHY/descriptor model,
covering reset prerequisites, firmware acknowledgement, PCI D0/MSI/MSI-X/ASPM,
NVRAM ownership, full/wrapped TX queues, RX bounds, 20,000 mutated return
descriptors, stale/invalid buffer cookies, fatal status, timeout paths, exact
matching and two independent functions. These tests establish software
invariants; no physical BCM5720 was available to establish hardware
interoperability or performance.

Other controller progress is tracked in [driver-status.md](driver-status.md).
